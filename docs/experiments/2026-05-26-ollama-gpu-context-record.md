# Ollama GPU 上下文实验记录

> 记录时间：2026-05-26
> 环境：Windows + NVIDIA GeForce RTX 5060 8 GB + Ollama + `deepseek-r1:7b`

## 结论

| 结论 | 说明 |
|---|---|
| `2048` 上下文不够稳 | 在同一检索上下文下，`num_ctx=2048` 出现了 `done_reason=length`，回答有被截断的风险。 |
| `4096` 更适合作为默认值 | `num_ctx=4096` 能更稳定完成长回答，输出完整度更高。 |
| 峰值显存主要由模型本体决定 | 从 2048 调到 4096 后，峰值显存变化不大，说明主要开销来自 `deepseek-r1:7b` 本体和运行时，而不是单纯上下文长度。 |
| CPU fallback 不是首要矛盾 | 真实推理时存在 CPU/GPU 分层，但主要瓶颈不是 CUDA 版本，而是 8 GB 显存余量和模型体积。 |

## 实测数据

| `num_ctx` | `num_predict` | 基线显存 | 峰值显存 | 增量 | 耗时 | 输出长度 | 结束原因 |
|---|---:|---:|---:|---:|---:|---:|---|
| 2048 | 1024 | 3324 MiB | 7288 MiB | 3964 MiB | 41.14s | 520 字符 | `length` |
| 4096 | 1024 | 3363 MiB | 7222 MiB | 3859 MiB | 36.23s | 797 字符 | `stop` |

## 推荐参数

| 参数 | 推荐值 | 说明 |
|---|---:|---|
| `llm_num_ctx` | `4096` | 默认上下文窗口，兼顾稳定性和显存占用。 |
| `llm_num_predict` | `1024` | 默认输出上限，降低长回答被截断的概率。 |
| 默认演示模型 | `qwen2.5:3b` | 更适合 8 GB 显存下的日常演示。 |
| reasoning 对照模型 | `deepseek-r1:7b` | 作为推理能力对照，保留即可，不再保留 `8b`。 |

## 备注

- 这次实验只使用了临时 prompt 拼接，不修改正式 `prompts/rag_summary_prompt.txt`。
- 终端输出已按 UTF-8 处理，避免 emoji 和中文在 Windows 终端里引发编码问题。
- `deepseek-r1:8b` 已计划删除，后续只保留 `qwen2.5:3b` 和 `deepseek-r1:7b` 作为主要演示模型。
